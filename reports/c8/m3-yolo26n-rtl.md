# C8 M3 冻结 Step 2 整帧与 Roofline

125/100 MHz 下，C8 发布候选实测 15,052,683 拍，较 C6 提速 3.570×，较 C7 提速 1.182×。距 14,143,000 拍底线差 909,683 拍。3.8× 与相对 C7 的 1.25× 均未达到。目标 4.5× 对应的 11,943,000 拍与本方案相差 3,109,683 拍。

各行使用同一 bus.jpg。C6/C7 取自冻结 Step 2 原始验收，C8 各行在同一 RTL 和对应时钟比重跑。每行的六个原始检测头共 176,400 B，分别与同版独立定点参考逐字节匹配。C8 输出还与 C7 逐字节匹配。所有行均为 0 ERROR、0 SLVERR、0 非法 DMA。SLVERR 依据冻结 MMIO 读写返回及 C99 HAL 异常检查。

## 物理瓶颈与固定命令序列的乐观下界

- NPU 16×16 DOT4 的理想吞吐为 1,024 INT8 MAC/NPU 拍。实测 NPU 4,088,652 忙拍包含输入读取、systolic 起停、K slab 和输出尾部。VPU 4,239,133 忙拍与 NPU 共用命令入口，合计 8,327,785 拍，形成串行资源下界。VPU 最大剩余项是多次字节 LUT、探测头 depthwise 的分拆与拼接，以及 Attention 的 NHWC 布局转换。
- GPU 归约耗 5,780,481 拍。单个 NPU K 命令最多 511，且没有通用跨命令的逐元素 INT32 初值。剩余最大的 model.3 和 model.5 仍各耗 1,662,138 与 1,096,319 GPU 忙拍。让 DMA、PS 派发完全免费时，固定计算工作量仍需至少 2,165,266 拍原生↔GPU 同忙才能到 4.5× 目标，当前实测 724,545 拍。
- DMA 搬运 24,326,368 B。256 位接口若每拍传一拍有效数据，理论下限 760,199 拍，实际 DMA 忙 1,025,681 拍（23.72 B／忙拍），观测利用率约 74.1%。真实 Step 2-v2 的 PS 数据通路另有总线位宽转换和 AXI 争用，本模型未计。三类引擎全部空闲共 970,360 拍。
- 将当前各阶段的实际忙拍固定，用 YHB 发射和栅栏序列计算关键路径。控制和 DMA 都零成本时为 13,382,071 拍。控制零成本、DMA 每拍 32 B 时为 13,891,706 拍。两者均慢于 4.5× 目标，对应当前实现的乐观天花板约 4.016× 与 3.869×。这个结果针对当前命令序列和已测服务时间，其他合法的编译序列或硬件改动有各自的上限。

优先建议 Phase 16 在 NPU 增加跨命令的全 M×N INT32 累加首值与合法行步长，目标是消除 GPU 的 578 万拍待归约工作。第二优先为 VPU 提供字级并行 LUT 和带步长的多路 Split/Concat/Transpose，以及允许 VPU 与 Tensor 独立排队的控制面。两项投入应分别用 M3 账本中的 GPU 和 VPU 工作量做回报验证。
