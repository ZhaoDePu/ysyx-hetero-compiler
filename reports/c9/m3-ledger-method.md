# C9 统一账本口径

iccd_master_metrics.csv 和 JSON 使用同一组数值。每行记录还原该行的原始日志、输出校验、频率比、时钟换算、权重来源和操作数口径。YOLO26n 保留 C6/C7/C8 独立档名。TinyLM 和分类保留 A0 至 A3。C4 因果 Attention 与 Transformer 同时保留历史 2:3 以及实测补齐的频率比。历史记录没有可核实的独立计数时，该字段为空。

整帧、完整提示会话和逐层聚合分别编码。所有速度比以同模型、形状和时钟比配对。分类器带匕首标记的加速比用 A0 完整代表层的加权聚合做分母。它包含各层独立派发，故不是全图 A0 的整帧拍数。跨频率表只在有相应时钟比回放时给出对应实测换算。200/150 MHz 和 125/100 MHz 均为冻结 Step 2 的受控测试时钟比。

执行时间的互斥分区由上报的重叠计数计算。三重重叠计入计算与 DMA 同忙，避免二次扣减。引擎利用率是各引擎忙拍除以壁钟拍，因此不能直接作为互斥总时长堆叠。融合 Attention 一条命令同时有 Tensor 和 Vector 工作，无法精确拆时的资料以合并计数或严格上界标记。

Roofline 横轴的算术强度用逻辑乘加工作量除以实际 DDR DMA 字节。纵轴由逻辑工作量和 RTL 壁钟周期换算。参考屋顶由冻结 Tensor 峰值、理想 DMA 接口宽度和观测最优 DMA 忙窗口带宽给出。它用同一 NPU 参考比较异构图，各模型的屋顶比例和 C8 固定发射序列接近度是不同指标。

Phase 16 的两项潜在收益分别按可归属的宽 K GPU 忙拍与 VPU 工作的可消除上界估计。该计算假设其他已测服务时间固定，至多扣除该功能的全部忙拍，且不能低于仍需工作的任一单引擎时长。融合 Attention 的整个 busy 区间只能作为 VPU 加速的宽松上界。两项收益不直接相加。
